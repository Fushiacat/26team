# План реализации и тестирования

**Последнее обновление:** 06.09.2026

## Цель

Создать Telegram-бота, который решает задачу матчинга участников хакатона за 3 шага: анкета → список подходящих → связаться.

## Входные требования

См. `PRODUCT.md`.

**Важные ограничения:**
- Бот должен работать в Telegram
- Не использовать платные API
- Простая архитектура 
- Быстрая реализация 
- Матчинг должен быть релевантным (показывать подходящие анкеты)

## Архитектурные решения

### Технологии:
- **Python** — основной язык (быстрая разработка, хорошая поддержка Telegram API)
- **aiogram 3.x** — асинхронная библиотека для Telegram ботов (современная, удобная)
- **SQLite** — простое хранилище данных (не требует отдельной настройки)
- **python-dotenv** — для работы с .env файлом (токен бота)

### Структура данных:
- **Users** — id, telegram_id, name, direction, role (seeker/organizer), description, created_at
- **Matches** — user_id, matched_user_id, status (pending/accepted/rejected)
- **Chats** — id, user1_id, user2_id, created_at

### Логика матчинга:
- Если пользователь "Ищу команду" → показать анкеты "Собираю команду" с подходящим направлением
- Если пользователь "Собираю команду" → показать анкеты "Ищу команду" с подходящим направлением
- Направление считается подходящим, если оно互补 (например, дизайнер ищет frontend, frontend ищет дизайнера)

### Что сознательно не используется:
- PostgreSQL/MySQL 
- Redis (не нужен кэш)
- Сложная авторизация (достаточно telegram_id)
- Веб-интерфейс (только Telegram)
- Алгоритмы машинного обучения для матчинга 

## Этапы реализации

### Этап 1: Базовая регистрация и анкета
**Наблюдаемый результат:**
- Бот запускается и отвечает на /start
- Пользователь заполняет анкету: имя, направление (одно из 4), роль (Ищу/Собираю), описание
- Данные сохраняются в SQLite
- Команда /me показывает текущую анкету
- Команда /edit позволяет обновить анкету

**Зависимости:** нет

### Этап 2: Логика матчинга (3-4 часа)
**Наблюдаемый результат:**
- Команда /find показывает список подходящих анкет
- Для роли "Ищу команду" → показывает "Собираю команду" с互补 направлениями
- Для роли "Собираю команду" → показывает "Ищу команду" с互补 направлениями
- Каждая анкета в списке имеет кнопку "Связаться"

**Зависимости:** Этап 1 (анкеты должны сохраняться)

### Этап 3: Функция "Связаться" (2-3 часа)
**Наблюдаемый результат:**
- При нажатии "Связаться" бот открывает личку с выбранным участником (отправляет ссылку на профиль)
- Альтернативно: создаёт временный мини-чат для обсуждения (оба участника добавляются в группу)
- Оба участника получают уведомление о новом контакте

**Зависимости:** Этап 2 (матчинг должен работать)

### Этап 4: Тестирование и отладка (1-2 часа)
**Наблюдаемый результат:**
- Все сценарии работают стабильно
- Обработаны краевые случаи (повторная регистрация, пустые анкеты)
- Тесты проходят

**Зависимости:** Этапы 1-3

## Стратегия тестирования

### Unit-тесты

**Что проверяется изолированно:**
- Функция сохранения анкеты (корректность данных)
- Функция фильтрации анкет (правильный матчинг по ролям и направлениям)
- Функция создания чата (корректность добавления участников)
- Валидация направления (только 4 варианта)

### Интеграционные проверки

**Какие части проверяются вместе:**
- Полный цикл: регистрация → матчинг → связаться
- Работа с реальной базой данных SQLite
- Отправка сообщений через Telegram API

### Ручной сценарий

**Действие пользователя:**
1. Запустить бота, нажать /start
2. Заполнить анкету: имя "Алексей", направление "09.03.01", роль "Ищу команду", навыки "frontend, React"
3. Нажать /find — бот показывает список подходящих анкет
4. Выбрать анкету и нажать "Связаться"
5. Проверить, что открылась личка или создан мини-чат

**Ожидаемый результат:**
- Анкета сохранена корректно
- /find показывает релевантные анкеты (тех, кто собирает команду и ищет frontend)
- Кнопка "Связаться" работает и создаёт контакт

## Риски и откат

**Риск 1:** Мало анкет в системе — матчинг не работает
- **Снижение:** Показать пользователю сообщение "Пока нет подходящих анкет, попробуйте позже"
- **Откат:** Добавить тестовые анкеты для демонстрации

**Риск 2:** Telegram API недоступен или rate limiting
- **Снижение:** Использовать асинхронные запросы, добавить обработку ошибок
- **Откат:** Локальное тестирование без реального бота

**Риск 3:** Сложности с созданием мини-чата (нужны права)
- **Снижение:** Использовать простой вариант — отправка ссылки на профиль в личку
- **Откат:** Убрать функцию мини-чата из MVP, оставить только личку

**Риск 4:** Потеря данных при перезапуске
- **Снижение:** Использовать SQLite с commit после каждой операции
- **Откат:** Резервное копирование базы данных
